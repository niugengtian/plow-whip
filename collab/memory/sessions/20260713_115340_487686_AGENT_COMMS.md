一、机制理解（基于真实代码/协议/状态）
架构：双真源（AGENT_PROTOCOL.json 规则+阵容，AGENT_STATE.json 任务+运行态）+ 唯一启动入口 start --json + 原子回写（task/handoff/inbox）。Hot/Warm/Cold 三层记忆；whip 探针零上下文，--crack 才 hydrate；dispatch 多通道（cursor_cli/codex_cli/zellij/file/notify/brain）；CLI 一任务一会话（R008/D-016）；revision+file_lock 防并发覆盖；原生 scheduler 跨 macOS/Linux/Windows。

二、现有能力（优势）
1) 协作效率：task/handoff 原子更新 owner/status/next/output/blockers，消除 Markdown 多文件漂移；drive 让 Desktop 编排 CLI 打工仔；dispatch_id 生命周期可追踪。
2) 快速接力：start --json 有界 payload（rules 摘要+task+定向 messages）；handoff 自动轮转会话；cli_sessions 绑定 resume；carry_forward 归档摘要。
3) 目标驱动自治：whip+scheduler --auto-continue 对 stale active 自动续作；CLI 通道可无人值守；Desktop 走 inbox/notify 等人接管。
4) 管理约束：R001-R008/P001-P003 分层（locked 不可覆盖）；permit 权限；禁止 rm/越界/未授权子 agent；doctor 校验 JSON/owner/派生字段一致性。
5) 故障恢复：wake_hash+30min 租约+最多3次重试防 token 风暴；CLI 超时杀进程组；pool failover 仅认证/限流类错误；state revision 冲突 fail-fast。
6) 跨终端连续性：zellij tab 绑定；file inbox 通用 fallback；projects_dir 配置解耦绝对路径；cli_sessions 冷归档。
7) Token 成本：probe 不加载 task 正文/协议全文；P001 禁止启动强制多读；memory-budget/rotation-health 量化；Brain 路由简单任务。
8) 可观测/可验证：doctor/memory-budget/rotation-health/inbox list/drive --status/scheduler logs；CLI 成功需 task marker 变化才判 success；verify_commands 字段预留。
